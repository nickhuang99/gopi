# The double-spelling slice — dispatch side single, guard side alive (verb-restructure 3/5)

This document is one run's RECORD — the measurement it made, the four
vocabularies it calibrated, the acceptance probes it drove, and what it did not
finish. The standing, re-derivable numbers it refers to live in
`devdoc/gopi-verb-census.md` (regenerated by `scripts/g7-verb-census.sh` and
gated by `cmd/agent/cli_verb_census_test.go`); nothing here is a second copy of
that table.

## The finding the slice started from

Measured with the real binary at `t+77s` of this run: the **dispatch side is
already single-spelled**. Each of the six spelling pairs this epic tracks has
exactly ONE dispatched word, and its twin is refused BY NAME by the guard:

| concept | dispatched (argv[0] accepted) | refused by name (exit 1) |
|---|---|---|
| code search | `code-search` | `code_search` |
| screen capture | `screen_capture` | `screen-capture` |
| ui state | `ui_state` | `ui-state` |
| vision analyze | `vision_analyze` | `vision-analyze` |
| voice input | `voice_input` | `voice-input` |
| keyword search | `keyword_search` | `keyword-search` |

**Why the refusal side is not "redundancy to clean up" (the operator's own
correction, `artifacts/verb-final-table-v2.md` §三, absorbing Hermes C4):** a
refused word is refused by an interceptor. Delete its line and `gopi code_search`
no longer refuses — it falls through to the bare-prompt path and buys a REAL
model call (a session directory, an `[auto] <word>` ledger row, tokens), which is
the `buildinfo` accident of 2026-09-30 reproduced. So the slice removes nothing
from the guard; it verifies the two sides against each other.

## The four vocabularies, calibrated by a DERIVED audit (Rule 38)

The audit is not a hand-typed list — it parses the sources and resolves every
word through its constant declaration (one hop of `pkg.Name` indirection, so a
leaf constant package such as `internal/cliverbs` is followed, never assumed):

| vocabulary | where it lives | source of the words |
|---|---|---|
| completion (`gopi <TAB>`) | `cmd/agent/cli_completion.go` | `topLevelCommandNames` |
| contract inventory | `cmd/agent/cli_contracts_test.go` | `dispatcherOfToken` keys |
| dispatch chain | `cmd/agent/*.go` | each `isXxxSubcommand` body, resolved through `CliVerbX` / `toolnames.ToolX` |
| refusal | `cmd/agent/cli_undispatched_tool_words.go` + `cli_verb_aliases.go` | the `word` / `alias` fields, with `dashTwin(X)` followed to X |
| guard (run path) | `internal/config/cli_verb_guard.go` | `config.PositionalVerbs` — read as the REAL exported value |

Five invariants, all holding at this base (the TSV is the run's own evidence,
`artifacts/spelling-audit.tsv`; the directory that produced it was deleted):

- **P1** a word is dispatched ⟺ it is not in the refusal vocabulary;
- **P2** a word refused at `argv[0]` is in `config.PositionalVerbs` (so the shape
  after a run flag — `gopi --timeout 3 <word>` — is refused too);
- **P3** a guarded word that is not dispatched is refused by name;
- **P4** for every derived pair (w, twin(w)) where both sides are known to this
  binary, EXACTLY ONE side is dispatched;
- **P5** the non-dispatched side of such a pair is in the refusal vocabulary.

```

completion  39                    code-search     true        code_search     false
contract    44                    keyword-search  false       keyword_search  true

guard       51                    ui-state        false       ui_state        true
refusal      7                    vision-analyze  false       vision_analyze  true
known       55                    voice-input     false       voice_input     true
== result ==
ALL INVARIANTS HOLD (P1..P5 + completion subset)
```

**No gap was found in the six pairs, so nothing was added to any vocabulary** —
and the invariant is now a committed test rather than a one-off reading:
`cmd/agent/cli_spelling_pair_test.go`.

That is the deliverable's "no gap" half, and its evidence is threefold: the
machine artifact `artifacts/spelling-audit.tsv` (the derived audit at this base,
exit 0), the two-sided live probe `artifacts/pairs-two-sided.txt`, and the new
test — which goes RED when the invariant is broken, measured twice on this tree
(transcript: `artifacts/mutation-red-proof.txt`):

- adding `"code_search"` back to `topLevelCommandNames` (simulating a second
  dispatched spelling) → `FAIL: both "code-search" and its respelling
  "code_search" are dispatched …`;
- deleting the `"ui-state"` line from `config.PositionalVerbs` (simulating the
  operator's own warning: removing a guard line) → `FAIL: … refuses "ui-state" at
  argv[0], but "ui-state" is missing from config.PositionalVerbs — \`gopi --timeout 3
  ui-state\` would still run it as a prompt`.

Both mutations were reverted (`md5sum` of the two files restored to the base
values listed below) and the test is green on the shipped tree. It reads every
word from the table it lives in — the four vocabularies above, `cliVerbs`, and
`config.PositionalVerbs` — so a new verb or a renamed spelling is measured by the
same code, with no hand-typed pair table to drift.

### The two-sided live probe — the discrimination that proves "dispatched"

the real binary in isolated homes. Each pair is probed on BOTH sides, and the two
sides answer differently, which is the whole point:

a usage error is not a failure of dispatch, and a probe that read exit status
alone would have called all twelve runs the same.

## The X11-leg finding (recorded because it changes what "真跑" can mean here)

`screen_capture` and `vision_analyze` were driven end to end against a real
display: `:1` on this host is a LOCAL X server (`xdpyinfo` answers), and
`gopi screen_capture --display :1 --out …` wrote a real 1920×1080 PNG
(`sha256_16` in the output above) that `vision_analyze` then read — the model
returned a description of it. The ambient `DISPLAY=localhost:17.0` is an
ssh-forwarded leg whose X server does **not** answer the setup handshake
(`connect to X display … no route answered; tcp localhost:6017: setup reply:
EOF`), so a probe that inherits it refuses without rendering anything. That is
why the probe takes the display as an explicit argument instead of inheriting it
— the same reason `cmd/agent/cli_contracts_test.go`'s `cliContractMasksAmbientDisplay`
masks `DISPLAY` for cases that do not need one.

`ui_state` answers only while a surface is ARMED (its dump exists while `gopi
chat`/`gopi ui` is running and writes it) — unarmed it refuses by name, which is
the designed behaviour, not a defect of this slice.

## Not Done (honest)

- **Nothing was removed from any vocabulary, because nothing was missing.** The
  slice's "clean up the dispatch-side redundancy" half was already done by the
  earlier slices; what this run adds is the PROOF (the derived audit + the two
  probe sets) rather than a diff to the tables. A reader looking for a code
  change in this branch will find only the regenerated census and this document.
- **The audit program itself is not committed.** It was a one-off (deleted after
  its TSV was captured, `cmd/spellingaudit/` is gone from the tree) because it
  was a whole-source PARSER — four vocabularies plus a one-hop constant
  resolution — shipped only to answer a question this run asked once, and
  shipping it would add a second census instrument beside the gate
  `cmd/agent/cli_verb_census_test.go` already owns (Rule 35: prefer what already
  runs). What survived it is the part worth guarding: the invariant is a committed
  test (`cli_spelling_pair_test.go`) that reads the same vocabularies the audit
  read, so the measurement is now re-runnable by the suite instead of by a
  throwaway binary. The TSV remains the evidence that the audit RAN; the test is
  what keeps the answer true.
- **`web_search` / `web_fetch` are NOT part of the slice — and measuring them
  turned up a real defect in the same family, which this branch does NOT fix
  (`artifacts/webtool-spellings.txt`, four probes in the isolated-home shape).**
  Two of the four spellings are refused by name and two are not:

  | word | measured | verdict |
  |---|---|---|
  | `web_search` | `exit=1`, `gopi web_search: retired — use \`gopi tool web search\`` | refused ✔ |
  | `web_fetch` | `exit=1`, `gopi web_fetch: retired — use \`gopi tool web fetch\`` | refused ✔ |
  | `web-search` | `exit=1`, **`Error creating agent: failed to create DeepSeek Claude client: deepseek: ANTHROPIC_AUTH_TOKEN not set`** | **fell through to the agent path** ✘ |
  | `web-fetch` | same as above | **fell through to the agent path** ✘ |

  That message is the run path's own: with credentials in the environment these
  two words are not a refusal but a **paid model call plus a session** — exactly
  the failure mode the guard exists to prevent, reached through the same
  dash/underscore twin pair this slice audits. The fix is one refusal arm per
  word, in the same tables the audit reads; it is a task of its own (the
  guarding of `web search` lives in `cli_websearch.go`'s
  `refuseWebToolFlatVerb`, whose spellings are not in any of the four
  vocabularies this audit derives, so the audit's P4/P5 pair test does not see
  them). Filed as a follow-up rather than fixed here — this branch's constraint
  is that the guard's refusal side stays byte-identical.
- **The `web_search` `-h` page teaches the opposite of what the binary does.**
  `gopi web_search -h` prints the retirement line AND then a page whose closing
  paragraph reads "The legacy flat verb gopi web_search still works (deprecation
  note on stderr) — gopi web search is the canonical form"
  (`cmd/agent/cli_websearch.go:90`), while `gopi web_search` (no `-h`) refuses.
  A reader of the help page is told a retired verb works; the contract test pins
  the retirement line but not the contradiction. Not fixed here (its correction
  belongs with the refusal-arm task above).
- **The `usage_log` / `doc_recipe` columns are a reading of THIS host's profile**
  (`~/work/GoPi` sessions, `devdoc/`), so a verb that ran on another host reads
  0 there. That is the census's own standing disclaimer, repeated here because
  the regenerated numbers are this run's reading.
