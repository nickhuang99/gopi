## 1. Verdict: nothing to re-apply — the intent is satisfied, and its byte form must not land

The branch was not a change to master's behaviour. It was an **investigation of a
red gate on master**, and every instrument it needed is regenerated by its writer,
never merged as text (Rule 38).

The defect it investigated: the generated verb index at the top of `COMMANDS.md`
records, per verb, the LINE of the predicate that dispatches it. A commit that
moves such a predicate and does not regenerate the doc leaves a stale cell, and
`internal/standards`' `TestCommandsDocGeneratedBlockMatchesSource` goes red on
master.

**Measured at this run's baseline (`89605e69c`), in the worktree:**

## 2. What the rework therefore does — the report survives, the fixture does not

The branch's durable product is its **evidence table**: the per-commit
attribution of who moved which anchor, when the stale pair entered mainline, and
how wide the red window was (mover `34c748033` at 16:09 moved
`isVersionSubcommand` 100 → 122 and touched no `COMMANDS.md`; the ingress was the
merge `5fa944558` at 17:31, whose own diff names no `COMMANDS.md`; the red window
on mainline was 5h28m). That reasoning is why the class is understood at all —
and it belongs in a `devdoc/`, which is the artifact a reader can find, not in a
`tasks/<task-id>-report.md` inside a branch that cannot merge.

Its **ruling** is carried here too: the old branch is a **NO-GO**, not because it
was wrong, but because it is a fixture whose every claim is re-derivable at the
current tip by one command (§3). A NO-GO on a branch whose subject is a
*regenerated* artifact is the ordinary outcome of Rule 38 — there is no text to
rescue, only a command to run.

**And the tip moved under it, measured to the minute.** The branch's tip
`ce1c11969` was authored `2026-10-13 20:07:31 +0800`; the commit that closed the
`gopi ui` cell **and** added the declaration-invariant it had just described —

## 3. The recipe (reuse, do not redo): how to decide this class on ANY tip

The gate's two red arms are **not** equally strong, and the branch's own
measurements prove it — worth stating as the operational rule:

- **The primary detector is the writer's own byte comparison.**
  `go run internal/standards/testdata/commands-census.go . COMMANDS.md --check`
  → exit 1 with "disagrees with the source" (`TestCommandsDocGeneratedBlockMatchesSource`
  is its test-side face).
- **The line-resolve arm is a WEAK extra detector.** Measured at `fcc335ebb`:
  the block arm was RED while `TestCommandsDocAnchorsResolve` stayed **GREEN**,
  because the stale `:125` happened to land on a **comment** line. At `6ef428c16`
  the same class reddened BOTH arms, because `:100` landed on a **blank** line.
  **A green resolve arm is therefore not evidence that the block is in sync** —
  the verdict is the writer's, never the anchor's.

So, on any tip:

```bash
go run internal/standards/testdata/commands-census.go . COMMANDS.md --check   # exit 0 = in step
go run internal/standards/testdata/commands-census.go . COMMANDS.md           # else: regenerate (ONE writer)
go test ./internal/standards/ -run TestCommandsDoc -count=1                   # the gate's own arms
```

A commit that moves a `func isXSubcommand` predicate must regenerate in the SAME
commit (`34c748033` and `612016700` are the measured shape of not doing so).
