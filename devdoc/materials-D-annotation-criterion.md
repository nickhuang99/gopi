# Devdoc: D 面标注框的结构判据 —— 框的边由像素定，不再由标定行距外推


**一句话。** `docs/archive/demo/materials/001-*` … `007-*`（D 面，`scripts/materials/gen-taskD.sh`
+ `scripts/materials/materials-render-D.py`）的 `04-annotated.png` 里，标注框过去是**用
标定行距外推**出来的（框的上下边 = `行槽`），而 `行槽` 本身也是外推的
（`round(y0 + pitch*k)`）。两处外推都带零点几像素的误差，于是**框线会穿过字形的笔画**、
**框里会压着两个字段**——而旧判据（"与目标行重叠 ≥ 一半、与别的行重叠 ≤ 一半"）恰好
在阈值上放行了这种形状。本文件记录判据怎么收紧、框算法怎么改成由像素定、以及为什么
"图看起来正常"不能作为验收。

## 1. 缺陷：旧判据在阈值上放行"骑两行"的框

旧判据（`materials-render-D.py` 原文）：

```python
verdict = "ok" if (ov >= hh * 0.5 and other <= hh * 0.5) else "MISALIGNED"
```

它问的是**比例**："框与目标行重叠够不够一半、与别的行是否不超过一半"。一个**骑在两行
之间、每行各压一半**的框正好落在阈值上——判定与浮点取整的边界重合时它就滑过去了。

实测（旧图，`git show 955706a1:docs/demo/materials/001-sandbox-create/03-raw.png`）：

| 量 | 值 |
|---|---|
| 框（manifest 声明） | `rect:1219x31+0+55` → `[55, 85]` |
| 目标行（行槽） | `[58, 82]` |
| 与目标行重叠 | 25 / 25 = **100%** ✅ 旧判据放行 |
| 与下一行 `[83,107]` 重叠 | 3 / 25 = **12%** ✅ 旧判据放行 |
| **框下边 y=85 切到的墨迹像素** | **29 个**（下一条命令的字形笔画） |
| **框内的墨迹段** | **2 段**：`[58,74]`（本行）+ `[83,85]`（下一行） |

比例判据看不见这两行——它只算了一个重叠数。而图看起来**完全正常**：框线压在字形上，
肉眼在缩略图里分辨不出来。

同一批测量还发现 **003-checkpoint-export 的现行图同样不合格**（框 `[180,210]`，
下边 y=210 切到 **40 个**墨迹像素，框内 2 段墨迹）——缺陷不是 001 独有，是算法的。

## 2. 根因（5-why 到机制，不停在"判据太松"）

1. **为什么框线穿过笔画？** 框的上下边 = 行槽的上下边 ± 3px。
2. **为什么行槽的边会落在字形上？** 行槽高 = 标定行距（取整过的 25px），而字形的
   墨迹只有 17px 高，基线在槽内的位置取决于字体；槽底落在大约"基线下方 8px"——
   那个高度**某些字形（下伸部）正好有笔画**。
3. **为什么行槽的边是算出来的而不是量出来的？** `row_bands[k] = round(y0 + pitch*k)`：
   用的是**取整过的**行距，真实行距带小数，每行漂零点几像素。
4. **漂到多少算错？** 到第 14 行漂 **2 像素**（实测 001：解说槽外推成 `[358,382]`，
   而那一行的墨迹实测是 `[356,374]`）；003 第 7 行外推 `[183,207]`、实测 `[183,199]`，
   多出来的 207 是**下一行**字形的上缘。
5. **所以判据为什么放行？** 判据量的正是这张**错的**行槽，而不是像素。外推的行槽把
   本行说矮了、把邻行说进来了——判据因此既可能误伤也可能漏放。

**结论**：要修的不是"阈值"，是**行槽与框都不许外推**——它们必须从像素量出来。

## 3. 修法：判据与框算法都改成"按墨迹量"

### 3.1 结构判据（`structural_check`）—— 三条像素命题

| # | 命题 | 为什么 |
|---|---|---|
| ① | 框的**上下边**所在像素行，在框的列范围内**没有墨迹** | 这就是"框不该穿过笔画"，也是"骑两行"的直接反面 |
| ② | 框内**恰好一段**墨迹 | 一个字段的笔画是连着的（字形纵向笔画贯穿多行），两个字段之间有行间空白（实测 8px）；两段 = 框里压着两个字段 |
| ③ | 那一段墨迹落在**框声称的那一行**的行槽里 | ②只保证"框里只有一个字段"，③保证"这个字段就是它指的那一个"——框整行漂一格时②会过、③才拦得住 |

判据与生成器**共用同一套 reader**（`ink_rows_in_box`/`ink_spans`）：判据量的是**同一张
未标注图**上的像素，不是 marks 字符串里的数字——"框对不对"与"框怎么算出来的"因此不可能
各说各话。

### 3.2 行槽由像素量（`measure_row_bands`）

量出全图的墨迹段（一行的字形是连着的，段间空白 ≥ 行距的 1/5），每段按
`round((top - y0)/pitch)` 认领它属于哪一行。认领必须**恰好一一对应**：非空行各得一段、
空行一段都没有；不成立即 FATAL（绝不把段丢给相邻的行）。这一条同时替掉了原来那句
"非空行必须有墨迹、空行必须没有"的自证——它现在是**构造本身**，不是事后校验。

### 3.3 框由像素定（`frame_around`）

从"这一行的墨迹段"向外让位（`BOX_PAD=3` 起，最多 `FRAME_TRIES=4` 次）：上下边各放在
墨迹段外面的空白行上，右边贴到这一行在列范围内的最后一个墨迹列。让不出去（图边、邻行
贴太近）就返回**诊断**、由调用方 FATAL——绝不悄悄把框挪到别的行上，更不手调坐标。

`SLOT_JITTER = 1`：行槽的上下边各缩进 1 行再找墨迹段。行槽高是取整过的整数而行栅格的
起点在小数上（003 第 7 行槽底那一行 207 是下一行字形的上缘）。`BOX_PAD(3) > SLOT_JITTER(1)`，
框线离那一位仍有 ≥2 像素。

### 3.4 顺带修掉的一个真缺陷：截图可能在 xterm 还没画字时拍下

`capture_screen` 的落定判据过去是"有非黑像素"（`ink_bbox`）。xterm 窗口刚映射出来是
**白底空窗**——`ink_bbox` 看到白底就报"有墨迹"，于是截图在**一个字形都没有**的时候被
接受（实测 002：截下来的屏幕只有两个颜色，纯黑 + 纯白），随后所有坐标全错。判据改成
"窗口矩形内**深色**像素 ≥ `PAINT_MIN_PX`"：白底不含深色像素，只有字形算。

## 4. 重产：只重画图，证据一个字都不动

`03-raw.png`/`04-annotated.png` 是**重产的**；`01-input.txt`/`02-output.txt` 是**证据**，
本次工作一个字都没改（`git status` 里它们不动）。为此 `gen-taskD.sh` 新增
`--render-only <out_root>`：

- 不重跑任何命令、不建沙盒（沙盒 profile 从 `00-entry.md` 的 `sandbox_profile` 取回，
  01 里的 `GOPI_HOME` 因此仍指向它真正跑过的那个）；
- 只用已存在的 `02-output.txt` 当输入重画两张图；
- 尺寸必须与旧图一致，否则拒绝覆盖（图像尺寸不是缺陷）；
- 入口卡保留 `measured_commit`（证据出自哪里）并新增 `rerendered_commit`（图在哪里重产）——
  两件事分开写，避免"这条素材是 203e8a40 跑的"这种误读；
- 收尾把两张图的 sha256[:16] 写进各条的「## 截图」一节（sha 的权威是**盘上的字节**），
  并断言 03/04 的 sha 不同（不同 = 标注真的发生过）。

## 6. 复用的配方（下次别再重造）

- **"框对不对"只能量，不能看**：任何"图看起来正常"的验收都是空的。判据必须是像素命题，
  且与出图**共用同一个 reader**。
- **任何"按标定值外推"的坐标都要问一句漂多少**：取整过的 pitch 外推到第 14 行就差 2px，
  而 2px 足以让框线穿过笔画。坐标要么量，要么带着误差预算。
- **比例阈值天然有边界形状**：凡是 `>= half` / `<= half` 这类判据，都存在一个正好骑在
  阈值上的输入。要用**结构**命题（有没有穿过、有几段、落在谁身上）替掉它。
- **离屏截图的落定判据不能是"有非黑像素"**：白色窗口本身就是"非黑"。要数**深色**像素。
