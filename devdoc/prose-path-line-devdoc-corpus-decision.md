# The devdoc BODY's inline `path:line` citations: the `prose-path-line` rung owns them (policy decision, task 01a13534)


**Task**: `01a13534-c0e1-7077-bd8b-070214150c1e` (peerbox, system layer — Rule 28)
**Decision**: the devdoc BODY is a **second corpus of the EXISTING reader**, not a fourth rung — the
same detector, the same one-red-arm verdict vocabulary, the same ONE freeze table, the same Rule 39
ratchet. The `in-range` arm stays **recorded, never red**, over both corpora.
**Evidence**: `~/.gopi/sessions/01a13534-c0e1-7077-bd8b-070214150c1e/artifacts/` — the scan tallies,
the generator's `--check` delta, and the devdoc-body red proof (`redproof-devdoc-past-eof.out`).

## 1. The gap this closes, and why nobody owned it

A devdoc BODY writes `internal/tools/task_finish_premerge.go:977` straight into its prose. Three
existing mechanisms each answer a different question over a different scope, and none of them reads
that token:

| mechanism | what it reads | verdict it can reach on a devdoc-body token |
|---|---|---|
| `anchor-number` census + gate | `devdoc/DOC-INDEX.tsv` **cells** (the machine-written copy) | `number-drifted`, when the recorded TEXT is still in the file — the BODY's own token is not a cell |
| `prose-anchor` census + gate | `tasks/*.md` (`ProseAnchorScanRoot`) | none — the devdoc corpus is not in its scope |
| `prose-path-line` census + gate | `tasks/*.md` (`ProseAnchorScanRoot`) | none — before this change the reader never opened `devdoc/` |

So a stale number in a devdoc body was invisible: not a manifest cell, not past-EOF-checked, not in a
frozen table. The manifest cell carries the SAME stale token, and IT has a permit
(`anchor-number-baseline.tsv`), which is how the pair stayed permanently green while `devdoc/hp-push-topology-audit.md`
told a reader the wrong line (`cli_tasks_worker.go:638` vs the real `650`).

## 2. What was measured, and the corpus that was chosen

Same reader, same region policy (fenced blocks skipped — a fenced region holds recorded tool output,
not a claim), `git ls-files`-free corpus walk:

| corpus | citing documents | mentions read | resolvable | `past-eof` |
|---|---|---|---|---|
| `tasks/` (unchanged, was already read) | 337 | 1860 | 930 | 21 |
| `devdoc/` (NEW) | 984 | 7235 | 3848 | 23 |

The devdoc figures are the epic's own measurement reproduced exactly (7235 mentions / 23 past EOF),
so the frozen population is comparable with the record that motivated the change.

**The corpus is `devdoc/*.md`, FLAT — top-level markdown only.** A recursive walk was measured in the
same run and is deliberately NOT taken: it would add 1793 mentions (4029 unresolved / 5641 resolvable
/ 5616 in range) and TWO further past-EOF sites
(`devdoc/requirements/11-build-and-repos.md`, `devdoc/requirements/merge-and-branches.md`). Those
sub-directories hold recorded evidence payloads (probe transcripts, capture runs, SDK snapshots) whose
churn would move this table for reasons that are not claims about the tree. The boundary is a
**named, measured, one-line step** a later task can take — it is `ProsePathLineCorpus.Paths`, not a
change to the reader.

## 3. The mechanism: one reader, one table, two corpora

- `ProsePathLineCorpora()` (in `internal/docclass/prose_path_line.go`) is the **one** declaration of
  the corpora; the reader, the per-corpus floors, the generator's header/usage and this doc all read
  it rather than spelling a directory (Rules 13/14). `ProsePathLineCorpusOf(doc)` is the **one**
  projection from a citing document to its corpus, and a finding CARRIES that attribution so a tally
  cannot bucket a document differently from the reader that read it.
- **The sibling rung's judgement surface is untouched**: `ProseAnchorScanRoot` is still `"tasks"`, and
  `prose_anchor_gate_test.go` keeps asserting the two corpora must not be conflated. The devdoc
  corpus was introduced INSIDE `prose_path_line.go`.
- **One freeze table** (`internal/docclass/testdata/prose-path-line-baseline.tsv`), regenerated by its
  own generator, went from 17 to **38 permits**: 21 real drifts just became owned, plus the devdoc
  corpus's own demonstrations (below).
- **Per-corpus floors** (`ProsePathLineDevdocReadFloor` / `ProsePathLineDevdocResolvableFloor`, and
  the totals kept) are checked by ONE guard, `ProsePathLineFloorBreaches`, which the generator calls
  before writing and the gate calls as its red arm. This is load-bearing, not decoration: `tasks/`
  alone carries 1860 mentions, so **a scan that never walked `devdoc/` clears every total this rung
  had before the widening** — only a per-corpus floor can see that, and only a per-corpus floor can
  tell "two corpora read once each" from "one corpus read twice" (Rule 15).

## 4. The `in-range` arm: RECORDED, NEVER RED — the decision, and the alternatives rejected

A `path:line` citation proves exactly one thing, and `in-range` is not it. `path` resolves and
`number <= lines` says the accelerator points INSIDE the file; it does not say WHICH line is meant, so
it is not a verdict a machine may red. Over the widened corpora that is 3825 devdoc + 909 `tasks/`
in-range mentions — turning them red would red a healthy tree thousands of times.

**Policy, recorded as the thing this rung will and will not answer, over BOTH corpora:**

1. `path` does not exist / is not repo-root-relative → `path-unresolved`, never red. Measured: 3387 of
   7235 devdoc mentions are unresolvable — branch-qualified paths, foreign absolute paths, plans,
   quoted prose — and a machine cannot tell "wrong path" from "a path that was never meant to be one".
2. `path` exists, `number <= lines` → `in-range`, **recorded and never red**. Content-level checking
   of a citation belongs to the rung that resolves a SYMBOL (`internal/agent`'s docanchor), not to a
   reader that only knows a file's length.
3. `path` exists, `number > lines` → `past-eof`: **the one red arm**, frozen in
   `prose-path-line-baseline.tsv` with a Rule 39 ratchet (a real-drift permit whose citation stopped
   firing is an ERROR; a withdrawn demonstration is allowed).

**Alternatives rejected, with the reason:**

- **Widen `in-range` into a coherence verdict (text-check the cited line).** Rejected: it needs the
  quoted span to resolve, which is the prose-anchor rung's identity — a different mechanism over a
  different corpus — and it would red every one of ~4700 citations the moment a file is reformatted
  above the cited site, on a corpus of RECORDS whose numbers are honest about the tree they measured.
- **Make the devdoc body's token the SOURCE and delete the manifest cell's copy.** Rejected *here*:
  that is a change to the manifest generator (`tools/docclass/classify.py`) and to the class contract,
  i.e. a different task on the same seam; and the cell's freeze was itself an accepted residual
  (`devdoc/docclass-anchor-residual-decision-20261012.md`). This doc does not overturn that decision —
  it makes the body's token owned alongside it.
- **Declare the body's numbers prose, not claims.** Rejected: the epic's own instance is provably
  wrong, `devdoc/base-align-head-start.md` names `internal/tools/task_finish_premerge.go:977` in an
  843-line file, and 23 such sites exist. "Not a claim" is what a surface says when nobody can check
  it; here the check is cheap and total.
- **A fourth rung (or a second freeze table).** Rejected: it would be a second spelling of one policy
  (Rule 14), a second place for a ratchet to go wrong, and the same detector would have to be written
  twice or shared anyway — sharing it is the widening this doc records.

## 5. Demonstrations in the devdoc corpus (a register entry per citing document)

The devdoc corpus quotes the SAME impossible stamps the report corpus registered:
`internal/tools/tasks.go:999999` and `internal/tools/guest_row_guard.go:9999` appear in
`devdoc/prose-path-line-citations.md` (the register's own decision doc), and the anchor gate's
`:9999` stamp appears in `devdoc/docanchor-gate-bare-lineno.md` (the doc recording that red proof).
A permit is keyed on `(ref, number, doc)`, so each quoting document needs **its own** register entry;
freezing them as `real-drift` would tell a reader this rung believes `tasks.go` is 999999 lines long,
and letting the gate red them would invite a "repair" that deletes the evidence a red proof rests on.
Three entries were added to `prosePathLineDemos` for exactly that, and
`TestProsePathLineDevdocDemosAreNotDrift` fails if a devdoc-corpus demonstration is classified as
drift or is missing its permit.

## 6. What this doc does NOT claim

- It does not claim the 21 newly frozen devdoc citations are all the devddoc body gets wrong — it
  claims the 23 provable `past-eof` sites are now owned, frozen, and ratcheted, and that the other
  ~7200 mentions have a verdict.
- It does not repair any citation. Rule 23: a devdoc body's number is repaired by a human editing
  prose; the table is the permit that keeps a healthy tree green until then.
- It does not widen to `devdoc/`'s sub-directories (§2: measured, deliberately not taken).
