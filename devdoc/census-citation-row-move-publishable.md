# The census citation deadlock: a row move is publishable when the reading IS the published tip

**Scope.** `internal/devworkspace/census_gate.go` + `census_redrive.go` — the clone
channel's census-citation leg inside ONE delivery attempt. This page states the rule
the leg now applies and why the previous rule could not be satisfied by any actor.

## The deadlock, measured

A branch that legitimately moves an ANCHORED line — it inserts one prose line in
`CONFIG.md`, so every `path.go:NNN` anchor below it points one line lower — makes the
census table's ROWS move. Measured on this tree in a scratch clone
(`/dev/shm/census-real-7cuz/repo`, HEAD `2831b3c`):

```
$ python3 -c "p='CONFIG.md'; s=open(p).read().split(chr(10)); s.insert(1,'A prose line this branch adds; every anchor below it moves down by one.'); open(p,'w').write(chr(10).join(s))"
$ git diff --numstat -- internal/standards/testdata/config-anchor-census.tsv
1	1	internal/standards/testdata/config-anchor-census.tsv
$ go run internal/standards/testdata/config-anchor-census.go . internal/standards/testdata/config-anchor-census.tsv
config-anchor-census: CONFIG.md — 213 distinct anchor(s) (read floor 190)
  2831b3c3f274181cdcf1129cfdd26b2a425219f1 [provenance: committed] (clean worktree: the reading is the revision)
wrote internal/standards/testdata/config-anchor-census.tsv: 213 row(s)
```

The re-derivation writes the citation for **the commit it measured** — a commit of
this branch. The channel's own `pull --rebase` then REPLACES that commit (it replays
the branch onto a moved base), and `git merge-base --is-ancestor <cited> HEAD` turns
red: the citation names a revision the push does not upload. So:

- re-derive → the citation is a local commit → the rebase rewrites it → blocked;
- `--at <tip>` → the citation is on the server, but the ROWS are another tree's rows,
  which the generator's own `--check` refuses against this tree;
- do nothing → the citation stays dead.

Every attempt re-derives, every rebase deletes the result, and master moving once
reopens the cycle. Row `01a1823e` measured three rounds of it, with the two escapes
named by the refusal sentence both dead ends:

```
$ git fetch origin && git rev-parse origin/master
c5241a2..985f53e  master     -> origin/master
985f53e1d1afa6bffa8c4b4a4b8f8dc779704983
$ git merge-base --is-ancestor 56b75e63b7c4b76c56ed49f52a73aacc8ca01108 HEAD
exit 1
$ go run internal/standards/testdata/config-anchor-census.go . \
    internal/standards/testdata/config-anchor-census.tsv --at origin/master
wrote internal/standards/testdata/config-anchor-census.tsv: 213 row(s)
$ go run internal/standards/testdata/config-anchor-census.go . \
    internal/standards/testdata/config-anchor-census.tsv --check
19 anchor row(s) differ
```

## The rule that replaces "rows moved ⇒ drift, discard"

The leg's job is never to CHOOSE between two readings; it is to publish the reading of
**the tree being published**. So it asks the object store one narrower question, after
re-deriving and before discarding:

| the revision the generator wrote onto `# measured-at:` | verdict |
|---|---|
| **is HEAD** (`grep -v '^#' \| cmp`'s equality with `git rev-parse HEAD`) | the rows ARE this push's tree's rows → **commit and deliver**. The citation rides the same push, because the commit it names IS the tip being published. |
| an ancestor of HEAD, a foreign revision, an empty citation, or a probe git cannot answer | nothing in this delivery measured these rows → **discard the regenerated bytes, keep the shipped refusal**. |

The criterion is `censusRederivedCitesPublishedTree` (`census_redrive.go`): ancestry
first (`git merge-base --is-ancestor <cited> HEAD`, which also refuses a revision this
clone merely keeps), then equality with `git rev-parse HEAD` (which refuses the
`--at <base>` shape — a table measured at the integration branch's tip is a reading of
ANOTHER tree). An unanswerable probe is FALSE: an unmeasured tree must never read as
measured-and-fine (Rule 15).

Two properties make this safe rather than convenient:

1. **Nothing is invented.** The bytes published are the generator's own output; this
   leg still composes no byte of the table (Rule 38).
2. **The safety is still a comparison, not a mood.** The narrow arm (citation-only) is
   unchanged, the discard arm is unchanged for every reading that is not the tip, and
   the refusal a caller sees now says *why* the reading was not publishable and names
   the command that repairs it.

## What the red arm now pins

`TestCensusRedriveRefusesWhenTheRowsDrifted` used to be driven by "a row moved", which
is exactly the condition the deadlock lives in. It is now driven by the defect it is
about — a reading of ANOTHER tree — through a fixture switch (`cite-parent.marker`)
that makes the generator cite `HEAD~1`. The two new arms pin the other side:

- `TestCensusRedrivePublishesARowMoveMeasuredOnThePublishedTree` — the green arm: the
  attempt's own `pull --rebase` rewrites the workspace's commit, the re-derive moves a
  row AND writes a citation naming the new tip, and the delivery lands.
- `TestCensusRederivedCitesPublishedTreeAsksTheObjectStore` — the predicate itself,
  over HEAD (true), a commit this tip does not carry (false), a directory that is no
  repository (false), and an empty citation (false).

Red proof: with the leg's condition reverted to `if rowsMoved {` the green arm fails
with the shipped sentence (`a row move measured on the PUBLISHED tree was refused as
"citation"`), and with the predicate deleted the file does not compile.

## What this does NOT fix

The citation is still a commit id, so the *citation-only* arm still depends on the
channel's re-derive running AFTER the attempt's rebase — which it does. What changes
is that the row-move arm no longer depends on anything: the table it publishes is the
tree it publishes, whether or not master moved, because the citation it writes is the
tip the push uploads.
