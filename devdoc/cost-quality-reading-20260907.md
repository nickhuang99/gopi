## 2. 成本洞察清单（核心交付）

### 2.1 缓存命中计费的"重叠累加"机制（已验证，P0）

**账单事实**（智谱 glm-5.3-flash，9-01~9-06，6 天）：
- 新增输入（未命中）仅 **1.77 亿 token**（每天约 2300~5300 万）
- 缓存命中 **24.17 亿 token** = 新增输入的 **~13.7 倍**
- 输出仅 466 万 token
- 9-01 单日命中 16.08 亿，占 6 天合计的 66.5%
- 9-01 请求 1.3 万次，每次平均命中 ~12.1 万 token，但真正新增输入仅 ~4000 token——**命中是新增的 30 倍**

**机制原理**（用户的直觉被确认正确）：
- 每轮 agent 循环（每个 tool call）都把**越来越长的对话历史从头重发**，历史前缀全部按缓存命中计费
- 当轮命中量 ≈ 上一轮累计输入（与历史重合的前缀部分），**不是**当轮新增量
- 累计命中 ≈ 0+1+2+…+(n−1) = **n(n−1)/2 二次增长**；累计新增仅 nK 线性增长
- 轮次越多，命中放大越狠——这就是"以为很便宜却花了钱"的根源

**为什么"以为很便宜"却花了钱**（智谱单日算账）：
- 命中单价确实最低：输出 1.4 元/千、输入 0.4 元/千、命中只要 0.115 元/千
- 但 9-01 命中 16.08 亿 token × 0.115 元/千 ≈ **184.9 元**，当天新增输入 5300 万仅 ~21.3 元
- **成本大头 = 反复重发历史产生的海量命中，而不是新说的话**

### 2.2 智谱 GLM vs DeepSeek 定价对比（P0）

| 计费项 | 智谱 glm-5.3-flash | DS v4-flash 空闲 | DS v4-flash 高峰 |
|---|---|---|---|
| 缓存命中 | 0.115 元/M | 0.05 | 0.10 |
| 输入（未命中） | 0.40 | 1.50 | 3.00 |
| 输出 | 1.40 | 4.50 | 9.00 |
| **miss:命中价差** | **3.5 倍** | **30 倍** | **30 倍** |

**核心差异**：DeepSeek 是"命中白嫖式"（命中 0.05 元/M 便宜到可忽略）但 miss 和输出贵得多；智谱是"均衡式"。
**这是用户当初被 DS 命中价吸引、走上 append-only 的原因**——30 倍价差下只要命中输入几乎免费，而智谱只有 3.5 倍、没有这个诱惑。

### 2.3 压缩策略实测：方向对，但 DeepSeek 有"坑"（P0）

用户新算法 = 类 Anthropic Claude Code 的 **micro-memory compaction**（微型记忆压缩：控制 request 长度、到阈值就压缩/改写前缀），实测效果：
- 压缩特征清晰可见：DS 每请求命中量 9-02 的 100K → 9-06 的 28.9K（塌了）；miss/请求 975 → 1780（升了）
- **输入侧确实省了**：9-06 每请求输入成本降 36%（砍掉的海量命中 × 便宜单价，省的绝对值盖过新增 miss）
- **但反直觉的关键点**：压缩省的是"命中"这条腿，而 DS 命中单价低到 0.05 元/M，**省的绝对值不大**；真正的账单大头是**输出 token（4.5~9 元/M）——压缩管不到**。9-06 输出 2082 万 token 单项 ≈93.7 元，比整个输入侧还贵
- **压缩的隐藏风险**：一旦前缀被迫改变（trim/压缩/并发乱序），"本来能命中的海量历史"瞬间按 miss 价 1.5~3 元/M 计费——**惩罚是 30 倍**。摘要每轮都变 = 永远无法命中，压缩把风险放大了
- **盈亏平衡点**：DS 上砍 1 个 miss 要砍 30 个命中才回本（极苛刻）；智谱（3.5 倍价差）才是压缩最划算的土壤——命中单价高（0.115）、miss 又不贵

### 2.4 两种上下文策略 × 两家模型（18:31 总结，P0）

**策略一 Append-Only**（只追加、永不改前缀，最大化 KV 缓存复用）：
- 对 DeepSeek：**有利**（命中极便宜 + 价差巨大 → 输入侧成本压很低），代价是上下文持续膨胀
- 对智谱：**收益有限、不合算**（价差小，省下的钱本就不多；命中 token 滚雪球式暴涨，总量放大慢慢吃掉那点优惠）

**策略二 Micro-memory compaction / 记忆压缩**（到阈值就摘要、裁剪旧消息、改前缀，维持舒适窗口保推理质量）：
- 对智谱：**成本代价可控，更适配**（价差不大，破坏缓存抬升有限；换来稳定推理质量，可接受）
- 对 DeepSeek：**高风险**（设计红利建立在高峰中率上；每次触发压缩就产生一批高成本 miss；= 主动放弃 DS 最大价格优势）

**模型行为差异**（额外维度）：DS 天然产出大量 thinking 内容，吃掉上下文预算，留给业务的空间被挤占；智谱 thinking 输出极少，同窗口下留给业务历史/工具返回的空间更多。

### 2.5 为什么纸上推演给不出确定答案（重要方法论）

- 两份真实账单跑同一套 agent harness，但 **token 分布不对等**：DS 自带大量 thinking 输出，智谱几乎没有
- 跨模型成本换算必须引入假设（输出比例、命中率、压缩触发频率）——每加一层假设不确定性 +1，调任意变量就翻转选型结论
- **唯一可靠落地路径 = 对照实验**：同一批真实 agent 任务 × 两套模型 × 两套上下文策略，采集各自的 hit/miss/output/请求数，拿到原生消耗与账单才能回答自己业务的问题

## 3. 质量洞察清单（"保质量"）

1. **1M 上下文只是指标，不是工作区间**：注意力在超长上下文会稀释，**一两百 K 内才是模型质量最佳区间**。标称最大上下文 = 可容纳上限 ≠ 最佳工作区间。
2. **长上下文劣化症状**：注意力漂移、早期关键信息被稀释、检索遗忘、推理逻辑变差。
3. **Append-Only 的质量代价**：拿到缓存成本收益，却承担 agent 推理质量逐步劣化的风险——**成本与质量在 append-only 路线上直接冲突**。
4. **压缩既是质量优化、也是输入侧成本优化**（用户判断被确认）：方向没错，但别指望它在 DS 上省出大钱（见 2.3）。
5. **核心两难**：没有一套策略能同时拿到"最低成本"+"稳定推理质量"。极致的钱 → DS+Append-Only 忍效果下滑；极致的质量 → 记忆压缩，DS 价格优势大幅削弱甚至消失；智谱两头都没有极端收益/损失。

## 4. 对我们工作（gopi / GLM / DS / 缓存现状）的可行动建议

> 每条标注来源（文件内段落）与落地点。

**A1. 立刻审计 gopi agent 的上下文前缀稳定性（成本+质量，最高优先）**
来源：16:33 段（重叠累加 13.7 倍 / 30 倍证据）+ 16:38 段。
如果 gopi 的 agent loop 是 append-only 且每轮重发完整历史，命中量就是二次增长。先查 gopi 会话里 system prompt 是否每轮原样重发、tool 结果是否全量累积。**若命中放大到 10+ 倍新增输入，说明大部分钱花在重发历史上**——这与文中账单同构。

**A2. 给 gopi 的 provider 计费侧加"缓存命中/未命中/输出"三列核算**
来源：16:38 段（DS 账单三列结构 + 9-06 输出 2082 万 ≈93.7 元 > 整个输入侧）。
省 DS 的钱要盯**输出 token**（压缩管不到），省智谱的钱才轮得到压缩。gopi 若只统计总 token 会完全错过这个分布。

**A3. 压缩/记忆策略的选择要按 provider 分叉——不能一套策略两家用**
来源：18:31 段。
- 若跑 **DeepSeek**：append-only 反而危险（前缀突变惩罚 30 倍）；记忆压缩 = 放弃最大价格优势。要么忍质量接受膨胀，要么接受涨价保质量——**两者只能选一个，别在中间反复横跳**（摘要每轮都变 = 永远 miss）。
- 若跑 **智谱 GLM**：记忆压缩是更适配的选择（价差小、代价可控、换来稳定质量）。
- 这条直接决定 gopi 未来若支持"记忆压缩"功能时**默认按 provider 差异化路由**。

**A4. 把输出 token 纳入 gopi 的质量/成本双指标监控**
来源：16:38 段（输出 4.5~9 元/M 是大头）。
DS 的 thinking 输出会吃掉上下文预算又占账单大头。若 gopi 上跑 DS，压缩/裁剪决策应优先砍"会引发长输出"的冗余输入，而不是盲目砍历史。

**A5. 不要相信价目表选型——gopi 该做的是一轮"同任务对照实验"**
来源：18:31 段（方法论）。
文中结论：纸面分析给不出板上钉钉的选型答案。可落地 = 拿 gopi 真实任务集，同批任务分别跑 GLM 与 DS、append-only 与压缩，各采集 hit/miss/output/请求数再比。**任何"GLM vs DS 谁便宜"的断言都只是倾向性判断，不是结论。**

**A6. 上下文上限设到一两百 K 的"舒适区间"而非标称窗口**
来源：16:52 段。
质量与成本双重理由：超长上下文注意力稀释（质量↓），且越长每轮重发越多（成本↑）。gopi 若做上下文预算管理，目标窗口应是 ~100-200K 有效内容，而非吃满标称窗口。
