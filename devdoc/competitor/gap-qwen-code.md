2. **这张表的分布是结构性的，读它的人必须先知道这一点。** 16 行「我强敌弱」+ 1 行「平手」，不是因为对方 16 个维度都差一档，而是因为**对方结构性没有 E3**：框架 §1 禁止为取证安装或运行第三方 agent（Rule 27 禁制造负载、Rule 35 禁新增持久依赖），所以对方的等级上限被锁死在 `partial`，而我方 17 维里有 16 维有本 run 的 `exit=0` 输出。在 `full=2 / partial=1` 的口径下，这个组合机械地落到「我强敌弱」。**「我强敌弱」这一列在这里的含义是「我方有运行证据、对方只有代码/文档证据」，不是「能力相差两倍」。** 谁要比较能力，得读证据列里的 `file:line`，不是读判定列。

3. **D07 那个「平手」不是打平，是两档同为 partial，而且对方在能力面上强于我方。** 我方停在 partial 的原因是 §3 的 full 证据串要求「**加载一个扩展后**，命令输出出现该扩展名」，本 run 只做到了「扩展点目录存在」（`ls -1 /home/user/.gopi/plugins` → `websearch`），没有做一次加载并让扩展名出现在输出里 —— 我按证据记账，不按能力记账。对方则三类扩展点齐备且有加载路径：MCP（`docs/users/features/mcp.md:20` 的 `mcpServers` 加载）、hook（`docs/users/features/hooks.md:5`，且 `:7` 说明默认启用、可用 `disableAllHooks` 关掉）、skill 目录（全树 path 里 `.qwen/skills/` 下 `autofix` / `bugfix` / `deflake` / `triage` 四份 SKILL.md，阶段 1 已取回 42 KB 的 `autofix` 正文）。**这一行是本表最需要往下读的一行。**

4. **对方在 E2 层面真正强于或并行于我方的地方，是这四维，值得单独记下来：**
   - **D11 屏幕驱动**：对方有 `cua.desktop`（`packages/node-repl/README.md:23` 原文「`cua.desktop` provides explicit foreground desktop input」）+ `app.getScreenshot()`（`:20`）+ 浏览器 SDK 两条腿，并打包成 MCP server（`:69` 的 `@qwen-code/cua-sdk@0.27.0` / `@qwen-code/browser-use@0.27.0`）。我方是单机 X11 的 capture + act，能力上是同一层，但对方把它做成了可分发的 MCP，作用域更宽。
   - **D15 代码智能**：对方是**原生 LSP**（`docs/users/features/lsp.md:3`：go-to-definition、find references、diagnostics、code actions），我方是 ctags 索引 + ripgrep 回退。LSP 是活的语义服务，ctags 是静态快照 —— 这一维我方拿的是「有」，对方拿的是「更准」。
   - **D12 本地服务面**：对方的 `qwen serve` 是守护进程 + Web Shell + API 同源（`docs/users/qwen-serve.md:9`，还有 `--no-web` 的纯 API 模式、`daemon start --save-token`），我方是一个内嵌 chat 页。同一层，对方的产品化程度更高。
   - **D9 执行隔离**：对方走 `bwrap`（`scripts/sandbox_command.js:97-98`）与容器镜像（`scripts/build_sandbox.js:42-45` 的 `dockerfile` 别名）两条腿，是**内核级**隔离；我方是私有 `GOPI_HOME` profile（`sandbox-gapqwen-d09-d25052cb` 下 `memory.db` / `sessions` / `raw` / `logs` 四件套 + 只读 `plugins` 链接）。我们的隔离管的是「gopi 的账本与会话不互相污染」，对方管的是「进程能看到什么文件」。**这两个不是同一件事，我把这一维判成「我强敌弱」只因为对方缺 E3，不因为我们的隔离更强。**
