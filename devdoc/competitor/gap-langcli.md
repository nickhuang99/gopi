## 结论

1. **对手的画像与它的血统一致**：Langcli 的包作用域是 `packages/@ant/*`、技能目录写 `.claude/skills/<name>/SKILL.md`（`src/commands/init.ts:171`）、`src/services/acp/agent.ts:2` 自述 "bridges ACP protocol methods to Claude Code's internal QueryEngine / query() pipeline"。这是**从 Claude Code 派生**的一条线，所以它在 D07（MCP + skills）、D11（computer-use）、D16（MEMORY.md）这几维上"看起来很强"，与 `gap-claude-code.md` 的读数高度同构。
2. **它唯一一维 `none` 是 D12（本地服务面），而这一格本 run 是逐点排除出来的**：`src/server/server.ts` 是自动生成的空桩（`startServer` 直接返回 `{stop(){}}`），`remoteControlServer` 起的是子进程，`bridge` 是出站客户端，ACP 与 MCP 都走 stdio。**没有一处对外提供本地 HTTP 服务** —— 这与它"CLI + Zed ACP Agent"的产品定位自洽（见 D12 行）。
3. **17 维里 14 维判「我强敌弱」，但这不是 14 个等价的领先**：它们全部是**同一件事的重复**——我方每一维都有本 run 亲自跑出来、带 `rc=0` 与原始输出的 E3，对方被规则（Rule 27/35）封在 E1+E2，等级上限就是 `partial`。**这 14 个差是证据通道的差，不是能力的差**，读这张表时不能当成 14 条技术优势。
4. **真正值得看的只有三行**：D01 与 D02 是**产品形态**的差（Langcli 有 OS 分支的安装器 + npm 分发，我们只有 `make install`，但没有首跑网关门槛）；D12 是**架构取向**的差（我们做本地服务面，它做 ACP/stdio 与远端 bridge）。其余各维的领先都是"我们跑过、它没跑过"。
5. **一处本 run 复核后上调的读数**：D01 我方按 `partial` 记（`make install` 无 OS 分支），而 `gap-copilot-cli.md` 的同格记的是 `full`。两者都不错，判据不同：那份文档把"具名命令 + 装出后 `--version` 有版本号"当 full，本文件额外要求框架 D01 原文的"对 OS 有明确分支"，故降一级。**这是判据的差，不是环境的差**，两处读数并列保留以便复核。
6. **诚实边界**：本 run 的 E3 全部由 `revision: 9189912e…` 的二进制执行，与该 ground HEAD 相等（`e3/D01-version.txt`）；对方侧全部是 `9c79f06` 固定 sha 上的正文行号，未安装、未运行 Langcli 一行代码，且**它的许可状态是"未授权"**（阶段 2 的 `cite-langcli.txt` 实测无顶层 LICENSE、`package.json` 无 `license` 字段）—— 因此这张表不构成任何"可借用"的推荐，只作功能性描述。
