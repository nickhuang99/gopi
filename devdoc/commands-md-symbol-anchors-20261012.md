# Task Report: COMMANDS.md's generated verb index keys on SYMBOL identity, not on a line number

Task `01a12e7fb5ef79d0bc044546bfab1599` · branch `task/01a12e7fb5ef79d0bc044546bfab1599`
· 2026-10-12

## Completed

**The defect.** `COMMANDS.md` publishes a machine-generated verb index whose rows carried
`file.go:<line>` anchors (`cmd/agent/cli_tasks.go:528` for `gopi task`). A line number is the address
of a name in ONE revision of ONE file, so **any** edit above it invalidates the anchor — including an
edit to a verb the row has nothing to do with. Measured twice in one day: `dcd25ce61` re-anchored that
row at 09:50, and `c6e93569e` (a change to a different verb's help text) invalidated it four hours
later at 13:04, turning `TestCommandsDocGeneratedBlockMatchesSource` red. This was the **eighth** round
of the family (`01a12414`, `01a12c14`, `01a12c24`, `01a12c6e`, `01a12c7d`, `01a12b8a`, `01a12dbf`,
and this one): each previous repair was itself a re-anchor, i.e. a reset timer, not a fix.

**The change — the anchor's identity is the symbol that the file DECLARES.**

1. `internal/cliindex` (`Verb.Ref` / `Verb.PredRef`) renders `file.go:<symbol>`:
   `cmd/agent/cli_verbs.go:CliVerbArchive`, `cmd/agent/cli_archive.go:isArchiveSubcommand`.
   - `AnchorSep` is a new exported constant and the **single** spelling of the separator: the gate
     builds its matcher from it (`regexp.QuoteMeta(cliindex.AnchorSep)`), so the renderer and its
     check cannot drift apart on the character while each stays green alone (Rules 1b/13/14).
   - `constDeclSite` now carries the **declaring identifier**: for an aliased spelling
     (`cli_verbs.go`'s `CliVerbMerge = cliverbs.Merge`) the anchor names `Merge` at
     `internal/cliverbs/cliverbs.go` — the file that actually declares it — not the re-export line
     (Rule 14). This is what keeps a symbol anchor from producing a false red.
   - `ConstLine`/`PredLine` stay on the struct (resolution needs them); they are simply no longer
     what the page publishes.
2. The gate's anchor predicate (`internal/standards/commands_doc_gate_test.go`) now reads **both**
   identities in one pass: `file.go:<symbol>` must name a symbol the file declares (via `go/parser`,
   the same declaration criterion `internal/docclass`'s `sym` tier uses — a symbol named in a comment
   or a string does **not** resolve an anchor), and the legacy `file.go:<line>` form is still checked
   (in range, not blank). The read-floor is unchanged and counts both.
3. `TestCommandsDocGateRedProofSymbolAnchorIdentity` — the new red/green proof: a renamed-away symbol
   is red; a symbol declared in **another** file (the MOVED case a repo-wide grep would pass) is red;
   and on a real churned fixture the symbol anchor stays green while the line anchor taken at the same
   moment goes red, which is the whole argument for the change.
4. `internal/cliindex/cliindex_test.go` (new) pins the renderer contract at the unit level: `Ref()`
   carries the symbol, `PredRef()` carries the predicate **function** name, and every line-move of a
   declaration leaves both byte-identical.
5. `TestCommandsDocGateRedProofStaleGeneratedBlock`'s dead precondition is repaired: it asserted
   `t.Fatalf` on "the committed document's block is already stale", so it failed exactly when master
   was stale — the moment a red proof is most needed. It now MEASURES the comparison (logged) and
   builds both the poison and the expectation from the render, so its red verdict no longer depends on
   the document's current state.
6. `COMMANDS.md` regenerated by its ONE writer
   (`go run internal/standards/testdata/commands-census.go . COMMANDS.md`), plus the two prose sentences
   that described the old anchor shape.

**A defect the new predicate caught immediately, and fixed here**: the first render produced
`isArchiveSubcommandSubcommand` — `readPredicates` strips the `is` prefix to key its index, and the
`PredicateFunc` accessor appended `Subcommand` again. The old line-number render never spelled the
symbol, so nothing had ever executed that construction. One spelling of the transformation now.

**Bonus, as the epic predicted**: the generated block's 88 line anchors are gone (the block publishes
symbols), so the drift surface inside `TestCommandsDocAnchorsResolve` shrank from 198 line references
to 110, and every one of those 88 rows is now immune to source churn.
