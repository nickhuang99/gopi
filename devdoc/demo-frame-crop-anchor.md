# 演示帧裁剪：锚点从"最长墨迹行"改成"终端客户区"

> 触发：arm1 在 HP 私有 Xvfb 上拍了 7 帧整屏（`full-clean-01..07.png`），
> 跑 `verify-frames.py` 四问 0/7。本文件记录**为什么旧的锚点必然错**，
> 以及新锚点 `docs/archive/demo/replay/crop-client.py` 用什么像素判据定位终端正文。

## 1. 旧锚点错在哪（可复算）

旧脚本 `crop-grid.py` 的锚点是"整屏最长的一段连续墨迹行"，注释里假设那是终端正文的
第 0 行分隔线（`─`×117）。在私有 Xvfb 上这条假设不成立 —— 屏幕上最长的那条线是
**metacity 的标题栏 + 菜单栏**：

```
full-clean-01.png (3000x1250, 根窗口黑)
  y=31..92   标题栏(235/250 灰) + 菜单栏      ← 跨度 2470px、覆盖率 1.000
  y=93..1186 终端客户区（终端底色 48,10,36）  ← 正文在这里（本批帧里是空的）
```

旧算法取到 `(264, 38)`：落在标题栏内部，于是裁出来的图从"Terminal"那行开始，
26 行的行槽整体错位，正文整块不在图里。实测把同一批帧按旧锚点裁 → 最后一条行带落在
**行槽 1**；按新锚点裁 → 客户区被正确框住（`WM框架带=(31,92)`、`客户区=(264,93,2734,1186)`）。

## 2. 新锚点的判据（全部是像素，无魔数）

`crop-client.py` 依次求四件事：

1. **屏幕背景** = 图像**最外一圈**的众数色。不能取"全图众数色"：终端占屏 86%，
   全图众数会取到终端底色 → 窗口外接框退化成整屏（实测锚点 (0,0)、网格越界）。
2. **窗口外接框** = 非屏幕背景像素的包围盒（`--window X,Y,W,H` 可给上界，可选）。
3. **客户区** = 外接框内**面积最大的非屏幕背景色**（终端底色）的包围盒。
   不要用"顶部高亮度整宽行带"来切框架带：metacity 下标题栏与菜单栏之间夹着一行过渡色，
   按"连续整宽"会中途 break，把客户区判成从菜单栏开始（实测锚点落进菜单栏）。
   而"谁占的面积最大"没有阈值可调。
4. **正文区** = 客户区减去**部件列**（整列 ≥90% 像素有墨 = 滚动条/边框）。
   滚动条落在客户区**内部**（实测 x=2726..2731），从两侧往里剥一步都进不去；
   不排除它，则"有墨迹的像素行"从第一行连到最后一行，行带塌成一条、四问行槽判定全废
   （实测：排除前 bands=1(0..1093)，排除后 bands=13）。

**验锚**：分隔线（跨度 ≥ 正文区宽 95% 且覆盖率 ≥85%）必须落在正文区 x/y 范围内。
找不到 = 这一屏的正文根本没画出来 → 打印 `EMPTY-CLIENT` 并 **exit 2**。
这是有意为之：本臂的头一批源帧（arm1 的 7 帧整屏）正文区里框线行数 0、墨迹色团 1、
每字符 0.00px —— 如果脚本"尽力裁一个最像的"，四问会给出一个意义不明的 NO；
如实报空正文，四问的 0/7 才指着正确的原因。

## 3. 怎么验证锚点是对的（可复算）

用**正控制**：同一台机器、同一 Xvfb 配方下 arm1 自己留存的、正文确实画出来的整屏
`t60.png` / `frame01.png`，跑同一条命令：

```
$ python3 docs/archive/demo/replay/crop-client.py arm1-raw/t60.png /tmp/t60-client.png
arm1-raw/t60.png -> /tmp/t60-client.png  锚点=(264,93) [窗口外接框=(264, 31, 2734, 1186)
  WM框架带=(31, 92) 客户区=(264, 93, 2734, 1186) 正文区=(264, 93, 2725, 1186)]
  网格=2462x1094 分隔线=y=113 x=265..2721 span=2457 cov=1.000 每字符=21.04px 字符格=(21.043, 42.077)
```

四问由 `verify-frames.py` 给出：`ctl-t60-clean.png` 的**最后行带落在行槽 25**
（26 行的最后一行）、色团 32、每字符 21.0px。旧锚点跑同一张图则落在行槽 0/1。

## 4. 教训（写进记忆的）

- **"最长墨迹行"不是终端正文的可靠锚点**：在有 WM 的屏幕上，标题栏/菜单栏总是更长。
  锚点要么来自**窗口几何**（`xdotool getwindowgeometry`），要么来自**面积最大色的包围盒**。
- **"有内容"的判据不能用"色数 > 3"**：标题栏+菜单栏本身就 >3 色，空正文也会被判为拍到了
  （arm1 的 `inner.sh` 就是这么放过了 7 帧空正文）。用**结构**判据：
  正文区里必须存在一条整宽分隔线。
- **同一批"7 帧"可能是同一张图**：arm1 的 `full-clean-01..07.png` 的 md5 全是
  `bb89a5aa733bdb9e4f054ba3173d78fe`。取证前先 `md5sum`，否则会把"1 帧重复 7 次"
  当成"7 帧都失败"来分析。
