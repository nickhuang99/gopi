【机制探测 M5：worktree / 分支生命周期】

目标：判断你自身产品是否原生管理"每个任务一份隔离工作区"——产品自己创建独立 git worktree + 分支、把任务放进去跑、结束后回收（清理 worktree 与分支），并能列出/查看这些工作区的归属。

硬性规则：
1) 只允许用你产品自带的 CLI 子命令或 flag；禁止自己手写 `git worktree add` 来模拟（那是你的 git 技能，不是产品能力）。
2) 必须真跑，逐字粘贴输出。

请按顺序执行：
(a) 列出你产品与 worktree/隔离工作区相关的原生子命令或 flag（逐字）。
(b) 真跑一次：用产品原生方式创建一个隔离工作区（可用一次性名字 `probe-m5-<产品名>`），并粘贴产品自己的输出。
(c) 列出它、查看归属（哪个任务/会话拥有它）。
(d) 回收它（或用产品命令清理）。

输出格式（最后三行必须是这三行）：
WORKTREE_CMDS=<实际运行的产品命令，分号分隔；没有写 NONE>
WORKTREE_RECLAIM=<回收命令；没有写 NONE>
M5_VERDICT=<NATIVE 或 NONE>
