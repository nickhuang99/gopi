【机制探测 M4：合并队列 + 推送闸门】

目标：判断你自身产品是否原生带"合并队列/推送闸门"——把分支合回主干时，产品自己强制检查：(i) 分支是否从主干派生（有共同祖先，不是无关历史）、(ii) 工作区是否干净（有未提交改动就拒绝）、(iii) 是否 fast-forward 可推；(iv) 是否有队列/串行化机制。

硬性规则：
1) 只允许用你产品自带的 CLI 子命令或 flag。禁止自己写 shell 脚本拼接 git 命令来模拟"闸门"（那是你的 git 技能，不是产品能力）。
2) 必须真跑，展示一次**被闸门拒绝**的输出（逐字粘贴）。

请按顺序执行：
(a) 列出你产品与合并/推送相关的原生命令或 flag（逐字）。
(b) 在当前 git 仓库里真跑一次合并动作，制造一个应当被拒绝的情形（例如：留下一个未提交的改动，或用与当前历史无关的分支），并粘贴产品自己的拒绝输出。
(c) 说明是否有"队列"（多个分支依次合并、串行处理）的机制。

输出格式（最后两行必须是这两行）：
MERGEGATE_CMDS=<实际运行的产品命令，分号分隔；没有写 NONE>
M4_VERDICT=<NATIVE 或 NONE>
